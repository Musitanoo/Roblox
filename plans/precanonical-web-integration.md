## Observable outcome

Add a bounded visual-conception layer before canonicalization and before any
production Blender build. Codex turns a gameplay brief and the selected
Salvaged Frontier constitution into a deterministic request packet. ChatGPT
Web Images may visualize that packet, but its result remains non-canonical
until it is imported, hashed, reviewed, rationalized and approved by a human.

The integration passes when:

- every request is schema-valid and bound to the exact art constitution;
- prompt, negative constraints, views and states are independently hashed;
- a preflight blocks contradictory, exhausted, duplicated or unsafe requests;
- a Browser doctor proves local runtime health without claiming task exposure;
- Web handoff is explicit, sanitized and never consumes quota by itself;
- no handoff claims generation readiness before `mcp__node_repl__js` is
  actually exposed by the current task;
- imported images retain conservative provenance without invented model IDs;
- no image can transition directly to `CANONICAL` or production approval;
- human selection is bound to the exact result digest;
- tests prove stale hashes, hidden fallbacks and budget overruns cannot pass;
- the installed workflow exposes the same commands and passes its full suite.

## Authority boundary

- Salvaged Frontier remains the sole world-identity authority.
- Industrial Toy Defense remains readability discipline only.
- ChatGPT Web Images is a replaceable visualization surface.
- Images are evidence of visible intent, not evidence of hidden geometry.
- Human selection authorizes canonicalization, not production.
- The visual canon remains the production source of truth.
- Blender and Roblox Studio retain their existing proof responsibilities.

## Milestones

### M0 — Contract closure

- Add closed schemas for briefs, policy, requests, preflight reports, handoffs,
  imported result manifests and human reviews.
- Add one versioned global policy with explicit states, budgets and forbidden
  fallbacks.

### M1 — Deterministic request compiler

- Compile a brief into `brief.md`, `prompt.txt`,
  `negative-constraints.txt`, requested views/states and `request.json`.
- Bind the current constitution path and SHA-256.
- Keep request generation deterministic and free of timestamps.

### M2 — Preflight and handoff

- Validate all hashes, the art-direction identity, budget and state.
- Detect duplicate successful prompt hashes in the asset result history.
- Produce a sanitized Web handoff without opening a browser or consuming quota.
- Require an explicit human-confirmation policy for actual submission.

### M3 — Result intake and review

- Import only local image files after Web generation.
- Copy raw bytes once, record SHA-256, dimensions and conservative provenance.
- Reject duplicate bytes and unsupported formats.
- Record `REJECTED`, `REVISION_REQUIRED`, `PRECANONICAL_CANDIDATE` or
  `HUMAN_SELECTED`; forbid `CANONICAL`.

### M4 — Workflow integration

- Add discoverable PowerShell commands.
- Add the precanonical phase to the `roblox-3d-asset` skill before canon
  compilation.
- Document the official browser adapters as external transport rather than
  pipeline authority.
- Add a reference barricade packet.

### M5 — Verification and installation

- Run schema/semantic validation, adversarial pytest, r3d tests and Luau checks.
- Package the release deterministically.
- Install with backups while preserving local human and generated-image
  evidence.
- Re-run the checks from the installed root wrapper.

### M6 — Controlled in-app Browser fallback

- Permit `codex_iab` only through explicit request selection.
- Keep `codex_chrome` as the default and the only attachment-capable adapter.
- Make preflight fail closed when `codex_iab` would require an upload.
- Preserve the same `chatgpt_web_images` provider, quota budget, prompt hash,
  provenance and no-API-fallback rules across both adapters.
- Prove the valid and invalid adapter matrices with schema and adversarial
  tests, then reinstall the hash-bound package.

### M7 — Task-scoped Browser capability correction

- Correct the false assumption that app-managed `node_repl` and native-pipe
  entries are necessarily stale or illegitimate.
- Add a local Browser doctor for plugin, backend, MCP tool and Chrome native
  host checks.
- Separate `WEB_PREFLIGHT_PASS`,
  `AWAITING_TASK_BROWSER_CAPABILITY` and actual generation readiness.
- Require a hash-bound doctor report before handoff creation.
- Keep task tool exposure `UNKNOWN` outside the Codex host and fail closed when
  the current task omits `mcp__node_repl__js`.
- Forbid repository scripts from invoking `node_repl` directly as a hidden
  browser-control proxy.

### M8 — Semi-automatic human operator bridge

- Add one command that recomputes preflight and opens a loopback-only operator
  interface.
- Compose and hash one exact submission text from prompt and negative
  constraints.
- Reduce human work to copy, paste, one generation, one download, one drop and
  one review decision.
- Validate upload size, image bytes, dimensions, format, duplicate history,
  generation budget and result identity automatically.
- Preserve conservative provenance and the existing non-canonical authority
  boundary.
- Bind a human attestation to the imported result without claiming invisible
  Web behavior.
- Make sessions resumable after result import while rejecting request,
  submission-text, attachment and output-path tampering.

### M9 — Object-by-state campaign operator

- Build one deterministic campaign from the six selected Salvaged Frontier
  visual canons and their sixteen required gameplay states.
- Require one distinct `gpt-image-2` generation for every object-state pair.
- Generate later states from the accepted previous state of the same object;
  independent state redesign is forbidden.
- Keep every request, imported image and review hash-bound and immutable.
- Turn an accepted review into an immediate transition to the next state or
  object instead of leaving the operator in a terminal blank state.
- Turn `REVISION_REQUIRED` and `REJECTED` into explicit, bounded new attempts
  on the same object-state; never retry automatically.
- Expose campaign progress, object navigation, state status, next-task preview,
  continuity references and a real completion screen in the operator UI.
- Preserve the legacy one-request operator for existing evidence.

### M10 — Fully navigable campaign explorer

- Keep all sixteen object-state tasks selectable before, during and after
  generation; never disable pending states.
- Separate read-only exploration from the active production workspace so
  browsing cannot mutate `currentTaskId`, evidence or generation budget.
- Expose status, order, continuity predecessor, decisions and complete
  attempt history for every state.
- Keep rejected and revision-required generations individually viewable.
- Add filters, previous/next navigation, keyboard navigation, deep links,
  browser history and a one-action return to the active task.
- Show explicit reserved placeholders and unlock dependencies for tasks that
  have not yet been generated.

### M11 — First-result audit and state-proof hardening

- Bind an exhaustive visual audit to the historical request, result, review
  and image without mutating any of those source proofs.
- Separate original exploration-stage compliance from downstream
  state-definition blockers.
- Require all assessment dimensions to pass and at least one preserve rule
  before an accepted review can advance the campaign.
- Require actionable correction rules for revision or rejection and a
  forbid-next rule for rejection.
- Lock one construction across the four state-board views and forbid
  cross-view component, repair, wear, material or state drift.
- Remove the canon contradiction that authorized a shape-only assembly mark.
- Supersede the unconsumed v1 campaign with a freshly compiled v2 campaign;
  preserve v1 as immutable history and consume no Web quota.

### M12 — Canon-driven review ergonomics

- Pre-fill accepted-review preserve rules from the exact state invariants in
  the bound source brief.
- Inherit the explicit preserve rules from the previous reviewed result when a
  later state or targeted revision carries a continuity attachment.
- Keep suggestions editable and human-confirmed; never auto-pass perceptual
  assessment dimensions.
- Restore suggestions on demand without overwriting human edits during normal
  navigation or re-rendering.
- Disable reviewer identity unless the decision is `HUMAN_SELECTED`.

### M13 — Versioned visual-authority correction

- Replace the robot/brute-biased `enemy_standard` source with the GDD-authorized
  violet zombie rôdeur, including closed anatomy, palette, states, invariants
  and role-separation rules.
- Give hostile biological assets their own material and prompt translation so
  player construction grammar can never leak into the zombie.
- Snapshot every canon bound to a consumed campaign before regenerating source
  authority.
- Fork a revised campaign that carries only unaffected accepted prefix evidence,
  records the source campaign hash and explicitly supersedes invalidated tasks.
- Resume at `enemy_standard/intact` without overwriting historical evidence or
  requiring the founder to regenerate accepted barricade and damage-effect work.

### M14 — Flexible object-lane generation and unrestricted prompt access

- Remove the global production-order gate while preserving one immutable task
  and one bounded generation per object-state.
- Make the first state of all six objects generation-eligible immediately.
- Let the operator explicitly activate any eligible object-state without
  rewriting unrelated evidence or consuming another task's budget.
- Keep `damaged` and `critical` bound to the accepted previous state of their
  own object; continuity remains local rather than global.
- Expose every task prompt at all times. Pending dependent states show a
  clearly labelled canonical preview until their exact continuity attachment
  exists.
- Add token-bound prompt and task-selection endpoints, UI actions and
  regression coverage for out-of-order lane execution.

### M15 — Lock-ready canon and GPT Image 2 semantic hardening

- Replace the archived retention-plan binding with the accepted retention
  doctrine without rewriting the immutable selected-constitution history.
- Add one schema-validated object-product contract covering falsifiable
  retention intent, gameplay-truth boundaries, orthogonal runtime-state
  coverage and asset-specific GPT Image 2 prompt discipline.
- Keep the sixteen primary object-state generations while explicitly
  separating structural reference states from operational overlays, transient
  reactions and terminal runtime states.
- Prevent a visual state from promising passability, collision, tracking,
  damage, repair or persistence that is not bound to an accepted gameplay
  contract.
- Replace shared physical-chassis prompt prose with object-class-specific
  identity locks, style rules, negative constraints and output self-checks.
- Compile per-state Salvaged Frontier translations so an intact prompt never
  describes a later damaged or critical state.
- Add semantic regressions for archived authority, template contamination,
  phantom states, unbounded horde-learning claims and incomplete prompt truth.
- Regenerate all eighteen candidate canons and a new immutable sixteen-task
  campaign. Preserve earlier campaigns as historical evidence.

## Recovery

- Generated preflight and handoff reports live under ignored `build/`.
- Raw Web results remain under the asset's `precanonical/results/` tree and are
  never overwritten.
- Installation uses staged validation and timestamped backups.
- Ordinary development edits the active workflow in place and uses targeted
  tests first. ZIP packaging and staged reinstallation occur only at an
  explicit release checkpoint or when installation behavior itself changes.
- No browser submission, quota consumption, API call, publication or Studio
  mutation is part of this implementation run.
